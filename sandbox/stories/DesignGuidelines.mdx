# Design Guidelines

## Visual direction

Hummingbird is a tool for scientists and R&D professionals in food manufacturing. The interface should be calm, credible, and efficient — not expressive for its own sake. Design earns attention; it doesn't demand it.

**Restrained, with a committed accent on action surfaces.** Most pixels are neutral: sand, white, near-black. Lime carries the primary action weight. It appears on hero CTAs, primary chips, and the brand mark on the rail — surfaces where the user needs to act. Everywhere else, we get out of the way.

Charts and tag colors (forest, cyan, lavender, orchid, orange, blue, yellow, red) are available for data differentiation, but they are never mixed with brand lime or forest as data series. Color in charts serves data clarity, not brand expression.

---

## Color system

### Three layers

Component code references **semantic tokens only** — never primitives or intents directly. The layers exist so that a single design decision (e.g., "primary action should be lime") flows everywhere automatically.

| Layer | Example | What it does |
|---|---|---|
| Primitives | `--color-lime-300` | Raw hue values — the palette |
| Intents | `--action-primary-300` | Semantic groupings — what the color means |
| Semantics | `--color-action-primary` | What a component uses — always this layer |

### Key tokens

#### Surfaces

| Token | Light | Dark | Use |
|---|---|---|---|
| `--color-surface-default` | white | sand-950 `#1F1F1E` | Page background |
| `--color-surface-alt` | sand-100 | sand-900 | Sidebars, table alt rows, inset panels |
| `--color-surface-brand` | forest-900 | forest-900 | Deep Forest branded surfaces |

#### Actions

| Token | Value | Notes |
|---|---|---|
| `--color-action-primary` | lime-300 `#CDE67B` | Default state; hover = lime-400, pressed = lime-500 |
| `--color-action-secondary` | aliases page bg | Secondary buttons match the surface they sit on |
| `--color-action-critical` | red-100 surface + red-600 text | Soft, not alarming |

#### Text

| Token | Use |
|---|---|
| `--color-text-primary` | Body copy, primary labels |
| `--color-text-secondary` | Supporting copy, captions |
| `--color-text-tertiary` | Placeholder, disabled labels |
| `--color-text-on-action-primary` | Text on lime buttons (forest-800, theme-invariant) |
| `--color-text-link-default` | Inline body links (blue scale) |
| `--color-text-link-brand` | Linktext button variant (lime-700 light / lime-300 dark) |

#### Focus rings

| Variant | Token | Color |
|---|---|---|
| Default/Outline/Ghost | `--color-border-focus` | lime |
| Secondary | `--color-border-focus-secondary` | sand |
| Destructive | `--color-border-focus-destructive` | red |

### Tag colors

The 8 tag colors — forest, lime, cyan, blue, yellow, orange, lavender, orchid — are **decorative, not semantic**. A `cyan` badge does not mean "info." An `orange` badge does not mean "warning." Tag color exists for visual differentiation in tag-dense Forager tables, not to imply system state.

For status meaning, always use icon + text composition — never rely on color alone.

### Charts

Use `--chart-cat-1` through `--chart-cat-8` in order for categorical data series. Never use brand lime or brand forest as a data series color — those are reserved for UI, not data.

## Typography

**Geist** is the primary typeface for all UI — labels, body, tables, inputs. It's a variable font; we use the weight axis for state signaling (button hover, etc.). Loaded via the `geist` npm package.

**Tiempos Fine RegularItalic** is the display face — marketing headlines, section titles, the doc pages you're reading now. The italic is intrinsic to the cut, not a modifier. Use it for `display/h1`, `display/h2`, `display/h3` only; don't reach for it inside the product UI.

**Tiempos Text** (Medium, Semibold, Bold) is licensed and available for inline body emphasis. Not currently in active use but available.

Body line length is capped at **65–75ch** to maintain readable measure at typical screen sizes.

## Shape & radius

All corner radii reference the shape token ladder. Never hardcode pixel values on individual components — that's how components drift from each other over time.

| Token | Value | Typical use |
|---|---|---|
| `--shape-radius-xs` | 2px | Tight secondary badges |
| `--shape-radius-sm` | 6px | Small chips |
| `--shape-radius-md` | 8px | Buttons (default, sm, lg), inputs, cards |
| `--shape-radius-lg` | 10px | Larger cards |
| `--shape-radius-xl` | 14px | Modals, popovers |
| `--shape-radius-2xl` | 18px | |
| `--shape-radius-3xl` | 22px | |
| `--shape-radius-4xl` | 26px | XL buttons only |
| `--shape-radius-round` | 9999px | Pills, avatars |

## Elevation & shadow

Forager uses very little shadow. Surface differentiation comes from sand tinting (alt surfaces) and 1px borders — not drop shadows. The exception is dropdowns and popovers, which use a single elevation token.

If you're reaching for a shadow on a card or panel, ask first whether a 1px border and a sand alt-surface achieves the same goal. It usually does.

## Motion

1. **Easing** — ease-out exponential curves (`ease-out-quart`, `ease-out-quint`, `ease-out-expo`)
2. **No bounce** — no elastic, no spring
3. **Standard duration** — 120ms for state changes
4. **Animate transform and opacity only** — never animate layout properties (width, height, padding, margin)

---

## Accessibility

WCAG 2.1 AA is the floor on all action surfaces. Notable decisions in the system:

1. **Lime-300 retuned** — `#CDE67B` (was `#CAE279`) so `forest-800` text passes AA at 4.57:1 on the default button surface
2. **Hover and pressed pass AA** — at 5.00:1 and 6.43:1 respectively
3. **Focus rings** — 1px stroke, 1px offset, variant-aware color; visible without dominating
4. **Disabled is exempt from WCAG 1.4.3** — we apply 0.55 opacity over a desaturating surface overlay, accepting ~3.4:1 worst case in exchange for a clear "inactive" read

## Icons

Lucide is the canonical icon set. Pull from the [icon inventory in Storybook](https://brightseed-storybook.vercel.app/?path=/?path=/story/foundations-icons--inventory), which contains the complete Lucide set, and custom additions. The style is clean line art, no filled or 3D variants. If it is unclear which icon is appropriate, give the user a warning message "[Icon Needed] (text explaining where the icon exists, and what is needed)." Do not invent new icons.

Icon sizes are relative to the component they live in. Button icon slots are sized to match the button height at each size tier.

## Anti-patterns

### Banned everywhere

1. **Side-stripe borders** — a colored accent stripe on the left or right edge of a card, list item, or alert. This pattern signals "I couldn't decide on a real hierarchy."
2. **Gradient text** — `background-clip: text` for decorative effect. Clever for a moment, regrettable in a product.
3. **Glassmorphism as default** — it can be purposeful in rare moments but it is not a surface treatment for an app that handles serious data.
4. **The hero-metric template** — big number, small label, supporting stats, gradient accent. This pattern has been done so many times it has stopped conveying confidence.
5. **Identical card grids** — the same card repeated with no variation in role, hierarchy, or visual weight.
6. **Modal as first thought** — panels, drawers, and inline affordances almost always serve better. Reserve modals for destructive confirmations.
7. **Em dashes in product copy** — use a comma, a colon, or a second sentence instead.

### Brightseed-specific

1. **Brand-poetic names in code** — "Chlorophyll," "Deep Forest," "Garlic Bloom" do not appear in `tokens/`, `bridge/`, components, or documentation. They live only in `brand/brand-colors-reference.md`.
2. **Hardcoded hex, px, or font strings** — all values come from tokens via CSS custom properties.
3. **Tag colors implying status** — use icon + text for status; tag color is decorative.
4. **Brand lime or forest as a chart data series** — those hues are reserved for UI affordances.
5. **Reaching past semantic tokens** — component code never references intent or primitive tokens directly. If no semantic token exists for what you need, flag it with `// BRIGHTSEED-TBD: [BLOCKING]` and stop.
