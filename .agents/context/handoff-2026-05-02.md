## Decisions and brief traceability

The structural correction Becky flagged in shape (surface header runs full-width above both columns, not framed inside the right panel) is implemented in `app-shell.tsx` and `surface-header.tsx` and used identically across both pages. This is the central restructuring move. AppShell does NOT impose a SurfaceHeader; the page renders its own. The header is page-owned content, not chrome.

The four-card identical-grid trap on Strategies is broken by the lead-recommendation treatment: lead card sits at the top with a small eyebrow label (lime dot + "Lead recommendation"), other three sit in a 3-up grid below with their own "Other strategies under evaluation" eyebrow. Still the same StrategyCard component, no per-role variant proliferation.

Compounds and Plants share a surface, not a route, toggle lives in the toolbar on the surface header, chat thread persists across the toggle. Matches the conversational exploration model in PRODUCT.md.

Tag colors stay decorative per DESIGN.md: cyan chips for gene targets, orange for source classification, forest for GRAS, lime for Open IP, yellow for IP Landscape, red for Crowded IP. Status meaning is carried by the icon (ShieldCheck / ShieldAlert / Shield), not by color alone, so the rule "color does not imply status" survives.

Editorial typography: large surface header title at 1.625rem with -0.01em letter-spacing, eyebrows in uppercase 11px tracking-wide, scientific names italic on PlantCard (anchored as the visible eyebrow per botanical convention). Chat assistant messages have no card chrome, gutter mark + body text, to reduce visual repetition next to user messages and saved chips.

No side-stripe borders, no gradient text, no glassmorphism, no hero metric. No em dashes (search confirmed). Brand-poetic names absent from code.

## What to push back on

A few choices I'd want a second opinion on:

1. **Lead-recommendation visual emphasis.** I committed to "subtle position cue + eyebrow" rather than a different surface treatment, to preserve grid rhythm. If this reads as too quiet, Anna might say "you can't tell which one is the lead", the next iteration is to make the lead card visibly larger (span 2 columns) or give it a faint surface-brand-subtle tint.

2. **Top bar density.** The top bar has project breadcrumb + "Active project" lavender pill. It's quiet by design (the surface header should win attention) but might read as too thin. The Mercury / Stripe references support this restraint, but if it feels under-loaded, options: add a project switcher dropdown, add a saved-items count, add a help/feedback affordance.

3. **Chat panel width at 360px.** Anna's mock has the chat narrower than the results. 360px works at 1280px+ viewports. Below lg (1024px) the chat is hidden. If you want the chat always visible, the breakpoints need a re-think.

4. **Saved state for compounds.** Right now saved-ness is page-local React state, not persisted. PRODUCT.md notes this is acceptable for the alpha case study but Meng will probably ask where the saved compounds GO, that's the "saved shelf" question I deferred in the brief. Defaulted to "no shelf this round."

5. **Strategies page chat panel.** Anna's strategies mock has a chat panel; my brief committed to it; I built it. But it might over-claim, at the strategies surface, the chat is asking about the project, not a specific strategy, so it could read as redundant with the surface subtitle (the goal). Open to trimming.
